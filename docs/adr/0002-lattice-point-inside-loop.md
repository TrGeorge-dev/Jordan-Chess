# 0002：闭环必须包含至少 1 个格点

## 背景

ADR-0001 改为八连通后，获胜变得太容易：4 子 X 形、4 子单位方格都能立即成环（X 形两条对角线交叉、面积 0 也算闭环）。用户提出增加规则"围起来的面积必须至少为一"。

审问澄清（grill-me）：
- **面积的定义 = 环内格点数**（不是鞋带几何面积）。用户明确选择"数格点"。
- "至少为一" = 环内包含 ≥1 个格点（交叉点）。
- 环内格点**有无棋子都算**（纯几何判定）。
- 由此 4 子单位方格（内部 0 格点）与 4 子 X 形（内部 0 格点）**不再构成闭环**——这推翻了 ADR-0001 中"X 形算有效闭环"的决定。

## 决定

闭环 = 顶点互异的八连通闭合折线（≥4 顶点，允许自交），**且环内包含至少 1 个格点**（射线法判定，环顶点不计入）。

## 为什么

- 4 子 X 形面积 0、单位方格内部无格点——它们"围了个圈但没围住任何交叉点"，是八连通下获胜过易的根源
- 4 子斜菱形内部恰有 1 格点，仍是合法的最小有效环；2×2 大方格（8 子）亦有效
- 与"围住格点才算赢"的直觉一致

## 被否决的选项

- **鞋带几何面积 ≥1**：单位方格面积 1 仍有效、X 形面积 0 排除——用户明确选择"数格点"而非几何面积。

## Consequences

- 环路检测需要找"能围住格点的路径"：BFS 最短路径常形成无格点小环，需 DFS 枚举绕行路径补找（路径条数/长度/总步数三重预算保护；密集棋盘 ~2s 内完成）
- AI 威胁判定（一步成环点）= 存在"含格点环"：V3 在 state 层实现 enclosing_cycle_exists（BFS+DFS+射线法）；Legacy 直接临时落子调引擎判定；搜索预算内定期检查，防止分析拖垮搜索
- 测试：单位方格/X 形不获胜、斜菱形/2×2 大方格获胜、棋盘格填色仍必然成环（斜菱形）
